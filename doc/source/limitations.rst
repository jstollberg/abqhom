Modeling assumptions and limitations
====================================

Cell geometry
-------------

* Automatic boundary detection is restricted to axis-aligned rectangular
  cells in two dimensions and cuboidal cells in three dimensions. A
  :class:`~abqhom.gmshmodel.Boundary` can describe a boundary that the
  automatic geometric search cannot identify, but the periodic group
  topology remains that of such a cell.
* A Gmsh physical group name must not conflict with the boundary-set names
  generated by ``abqhom``.

Boundary conditions and kinematics
----------------------------------

* Periodic boundary conditions require one-to-one matching nodes on opposite
  boundaries. The Gmsh workflow creates these relations before meshing;
  :meth:`~abqhom.gmshmodel.GmshRVE.read_from_mesh` checks them for an imported
  mesh.
* Periodic rotations of beam and shell nodes are supported for zero imposed
  macroscopic curvature. The effective medium is a first-order Cauchy
  continuum; macroscopic couple stress and curvature are not identified.
* Affine displacement boundary conditions are restricted to elements without
  rotational degrees of freedom. Use periodic conditions for beam and shell
  cells.
* Elements with warping degrees of freedom are not supported. Unsupported
  element types are rejected instead of silently omitting their degrees of
  freedom.

Periodic boundary elements
--------------------------

By default, :class:`~abqhom.abqmodel.AbaqusRVE` removes redundant element
copies associated with secondary periodic boundary entities. Their nodes are
retained so that the periodic equations remain applicable. Constructing the
model with ``remove_secondary=False`` is useful for inspecting or visualizing
the complete periodic representation, but the resulting unweighted model is
not an ownership-consistent boundary-value problem when structural members
are duplicated on the cell boundary.

Execution environment
---------------------

The Abaqus-facing API must run in the Abaqus CAE Python kernel. The package
uses Abaqus for all element formulations, material integration, nonlinear
solution procedures, and output databases; it is not a standalone finite
element solver.
