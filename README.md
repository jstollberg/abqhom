# abqhom

[![License: GPL v3](https://img.shields.io/badge/License-GPLv3-blue.svg)](LICENSE)
[![Documentation Status](https://readthedocs.org/projects/abqhom/badge/?version=latest)](https://abqhom.readthedocs.io/en/latest/?badge=latest)

`abqhom` is an open-source Python framework for first-order computational
homogenization of periodic two- and three-dimensional unit cells. It connects
geometry and periodic meshing in [Gmsh](https://gmsh.info/) with finite element
analysis in [Abaqus](https://www.3ds.com/products/simulia/abaqus) and supports
continuum, truss, beam, and shell constituents, including mixed-dimensional
cells, finite kinematics, and path-dependent material behavior.

The package supplies the scale-transition machinery around an Abaqus
analysis. Abaqus remains responsible for element formulations, constitutive
integration, nonlinear solution procedures, and output databases.

## Capabilities

- **Mixed-dimensional periodic cells.** Continuum, truss, beam, and shell
  constituents may occur separately or in the same model. Nonconforming
  structural and continuum meshes can be connected through Abaqus embedded
  constraints.
- **Linear and nonlinear response.** Macroscopic loading is prescribed through
  the displacement-gradient history. Finite rotations, geometric
  nonlinearity, nonlinear elasticity, plasticity, and other material models
  are handled by the selected Abaqus step and constitutive definition.
- **Periodic and affine boundary conditions.** Matching periodic meshes are
  generated in Gmsh or verified for imported meshes. Periodic translations
  and, where present, nodal rotations are constrained automatically. Affine
  displacement conditions are available for cells without rotational degrees
  of freedom.
- **Ownership-consistent structural boundaries.** Redundant copies of
  structural elements on secondary periodic boundary entities are removed
  before analysis while their nodes are retained for the periodic equations.
  No stiffness or constitutive-parameter scaling is required.
- **Element-type-independent effective response.** The effective first
  Piola–Kirchhoff stress is recovered from element nodal forces. Incremental
  microscopic work, including moment–rotation contributions, is available
  for an independent discrete Hill–Mandel check.
- **Geometry and mesh flexibility.** Cell constituents are identified through
  Gmsh physical groups. Existing periodic meshes can be imported with
  `GmshRVE.read_from_mesh`, including meshes generated by external geometry
  tools.
- **VTK export.** Results can be exported through
  [Paraqus](https://github.com/InstituteOfMechanics/Paraqus), including stored
  beam and truss radii for visualization.

## Scope and limitations

The automatic boundary classification assumes an axis-aligned rectangular
cell in two dimensions or a cuboidal cell in three dimensions. The
constituent topology inside and on that boundary may be general.

The current framework identifies a first-order Cauchy effective response:

- periodic meshes require one-to-one matching nodes on opposite boundaries;
- periodic rotations are supported for zero imposed macroscopic curvature;
- affine displacement conditions do not support rotational degrees of
  freedom;
- elements with warping degrees of freedom are rejected;
- the Abaqus-facing API must run in the Abaqus CAE Python kernel.

See the detailed
[modeling assumptions and limitations](doc/source/limitations.rst) for the
complete scope.

## Workflow

An `abqhom` analysis has two layers:

1. `GmshRVE` identifies the cell boundary, defines or verifies periodic mesh
   relations, generates or imports the mesh, and constructs the node and
   element sets required by Abaqus.
2. `AbaqusRVE` imports that representation, removes redundant periodic element
   copies by default, assigns sections, applies macroscopic boundary
   conditions, runs the analysis, and recovers effective quantities from the
   output database.

In compact form:

```text
Gmsh geometry or mesh
        -> GmshRVE
        -> AbaqusRVE
        -> constrained RVE analysis
        -> effective stress and power checks
```

## Requirements

- **Abaqus** CAE and solver. Scripts using `AbaqusRVE` execute through, for
  example, `abaqus cae noGUI=main.py`.
- **Gmsh 4.9.4 or newer** with its Python API and shared library.
- **NumPy**, which is included with supported Abaqus installations.
- **backports.weakref**, installed in the Abaqus runtime for compatibility
  with legacy Python 2.7 releases.
- **Paraqus 1.0.2 or newer**, used for VTK export. The oldest compatible
  release currently available from PyPI is 1.0.4.

The code is compatible with both the Python 3 environment of current Abaqus
releases and legacy Abaqus installations using Python 2.7. The examples may
require a full Abaqus license, depending on their model size.

`microgen` is used only to regenerate the mesh of the gyroid tutorial. It is
not a runtime dependency of `abqhom` or Abaqus.

## Installation

Install `abqhom` in a regular Python environment and use the supplied helper
to create an isolated runtime for Abaqus. The Abaqus installation itself is
not modified, so this workflow also works without administrative access.

Install the package and create the runtime:

```console
python -m pip install abqhom
abqhom-install-abaqus
```

The helper creates a versioned prefix below `~/.abqhom/abaqus-runtime`. It
installs only abqhom, Gmsh, Paraqus and `backports.weakref` there, without
their dependencies. In particular, no external NumPy is exposed to Abaqus.
The command prints the resulting `site-packages` path and writes activation
scripts next to it.

Activate the runtime in the shell from which Abaqus will be launched. For
example, on PowerShell use the path printed by the helper:

```powershell
. "C:/Users/name/.abqhom/abaqus-runtime/.../activate_abqhom.ps1"
```

On Linux, source the generated shell script:

```bash
. ~/.abqhom/abaqus-runtime/.../activate_abqhom.sh
```

The generated path may instead be added to the environment setup of a job
scheduler. Only the dedicated runtime `site-packages` directory is exposed;
packages from the Python environment used to run the installer are not added.

For a source checkout, first run `python -m pip install .` and pass the local
source or wheel to the helper with `--abqhom-source`.

## Quick start

The simple-cubic lattice is the shortest complete example. From an Abaqus
command prompt:

```console
cd examples/beam_lattice_simple_cubic_3d
abaqus cae noGUI=main.py
```

The script builds and periodically meshes the lattice in Gmsh, imports it into
Abaqus, applies a macroscopic strain, evaluates the effective response, and
compares the axial modulus with its analytical value. Results are written to
`results/`, and VTK output is written to `vtk_output/`.

See the complete
[`beam_lattice_simple_cubic_3d/main.py`](examples/beam_lattice_simple_cubic_3d/main.py) source
for the minimal API sequence. The broader tutorial collection is described in
[`examples/README.md`](examples/README.md).

## Public interface

| Module | Main interface | Purpose |
|---|---|---|
| `abqhom.gmshmodel` | `GmshRVE`, `Boundary` | Geometry, boundary classification, periodic meshing, and set construction |
| `abqhom.abqmodel` | `AbaqusRVE`, `LoadHistory` | Abaqus model construction, sections, boundary conditions, analysis, averaging, and VTK export |
| `abqhom.utils` | conversion and verification functions | Voigt/tensor conversion, Hill–Mandel residual, mixture bounds, and CSV export |

The principal post-processing methods are:

- `AbaqusRVE.average_stress` for the effective nominal stress;
- `AbaqusRVE.average_power_increment` for microscopic incremental work;
- `AbaqusRVE.get_volume` and `AbaqusRVE.get_frame_time` for cell and output
  metadata;
- `AbaqusRVE.export_to_vtk` for VTK visualization through Paraqus.

The complete API is documented in [`doc/source/api.rst`](doc/source/api.rst).

## Examples

Concise tutorials under [`examples/`](examples) cover:

- beam and shell lattices in two and three dimensions;
- continuum composites and inclusions;
- embedded beam–continuum coupling;
- finite-strain Neo–Hookean response;
- cyclic perfect plasticity;
- imported periodic gyroid meshes.

The larger [`paper_examples`](examples/paper_examples) reproduce the numerical
studies accompanying the computational-homogenization manuscript:

| Example | Study |
|---|---|
| [`01_small_strain_verification`](examples/paper_examples/01_small_strain_verification) | Small-strain mixed continuum–shell–beam verification |
| [`02_hyperelastic_octet_lattice`](examples/paper_examples/02_hyperelastic_octet_lattice) | Imperfect hyperelastic Octet lattice, periodic buckling, and supercell check |
| [`03_elastoplastic_sandwich_cell`](examples/paper_examples/03_elastoplastic_sandwich_cell) | Elastoplastic sandwich cell, cyclic response, and effective yield surfaces |

Execution notes for the manuscript cases are collected in the
[`paper_examples` README](examples/paper_examples/README.md).

## Documentation

The Sphinx documentation in [`doc/source`](doc/source) contains the
installation guide, modeling assumptions, user workflow, example overview,
API reference, and testing instructions.

Build it locally with:

```console
python -m pip install -r doc/requirements.txt
sphinx-build -b html doc/source doc/build/html
```

Solver and meshing modules are mocked during the documentation build, so an
Abaqus or Gmsh installation is not required to render the documentation.

## Tests

Tests are split into a Gmsh-only group and a group requiring the Abaqus
kernel. Both runners load Gmsh exclusively from the explicitly supplied
module directory, isolate generated files in a temporary directory, and write
a report to the current working directory.

Run the complete suite from the Abaqus Python interpreter:

```python
import abqhom.tests as tests

tests.run_abaqus_tests("C:/path/reported/by/abqhom-install-abaqus")
```

Run only the Gmsh and utility tests from a compatible Python interpreter:

```python
import abqhom.tests as tests

tests.run_python_tests("C:/path/reported/by/abqhom-install-abaqus")
```

Failed test runs retain their temporary artifacts for inspection. See
[`doc/source/tests.rst`](doc/source/tests.rst) for details.
